# MiSS 训练优化计划

[English](OPTIMIZATION_PLAN.md) | 简体中文

## 基线

首次大模型运行使用：

```bash
./build/rwkv_miss_tune \
  --model /mnt/nvme0n1/rwkv7-g1j-7.2b-20260831-ctx16384.pth \
  --data /mnt/nvme0n1/html_vibe_datasets/3d/3000_training.jsonl \
  --output nora_output \
  --vocab ./assets/rwkv_vocab_v20230424.txt \
  --rank 16 --alpha 16 --targets all \
  --ctx 4096 --chunk 1024 --batch-size 8 --epochs 1 \
  --lr 0.0001 --lr-final 0.00001 --warmup-steps 10 \
  --save-every 100 --wkv_tape
```

在 RTX PRO 6000 Blackwell Workstation Edition 上完成 26 次优化器更新，没有显存不足
或非有限损失。模型加载后，运行显存约 22.0 GiB，持续吞吐约 2.14k token/s。
238 秒稳定 GPM 采样结果：

| 指标 | 均值 | 观测范围 |
|---|---:|---:|
| GPU 忙碌率 | 99.8% | 92–100% |
| 功耗 | 401.6 W | 362–427 W |
| SM 活跃度 | 52.0% | 49–55% |
| SM 占用率 | 12.9% | 12–14% |
| Tensor/HMMA 活跃度 | 15.4% | 12–18% |
| DRAM 活跃度 | 20.9% | 19–24% |

普通 GPU 忙碌率容易误导：队列持续有工作，但设备真正发出 Tensor Core 运算的周期比例
较低。冻结 7.2B Linear 前向和输入梯度工作的粗略吞吐下界为
`4 * 7.2B * 2.14k = 61.6 TFLOP/s`，未计入 WKV、输出头、MiSS、逐元素操作和填充，
不能当作精确的实际 FLOPS 结果。Nsight Compute 计数器当前因 `ERR_NVGPUCTRPERM` 无法访问。

## 测量前置条件

修改算子前，在预热后用 Nsight Systems 采集一次优化器更新，启用 CUDA、NVTX、cuBLAS
和操作系统运行时追踪。为样本、分块、层、基模 Linear 前向、基模 dX、WKV 前向/反向、
MiSS 归约、MiSS 投影、dD、scatter-dX 和优化器更新添加 NVTX 区间。
从同一次追踪导出：

1. CUDA GPU 算子汇总和 cuBLAS 调用汇总。
2. 算子启动间隙和 CPU 启动线程利用率。
3. 前向、反向、重放和优化器更新各区间的墙钟时间。
4. 每种重复形状的 GEMM 维度、数据类型和算法。

每个结果需保存命令、提交、驱动、频率、数据行、预热次数、token 数和原始 GPM CSV。
比较至少十次预热后更新的步耗时中位数。测量窗口内不混入测试进程。

## 优化阶段

### 1. 实现真正的并行微批次

`--batch-size 8` 当前顺序运行八个样本，仅累积梯度，这是最大的结构性利用率限制。
为状态、注意力/FFN 移位、`v_first`、WKV 前向/反向和分块记录增加批次维度。
将多个样本的等长分块合并为一次算子启动和一个更大的 Linear GEMM，同时保持各样本
循环状态独立。

采用长度分桶和有效性掩码处理最后一个不完整分块。沿用有效 token 加权方式累积损失
和 dD。先实现固定批大小 2，完整序列与分块梯度测试通过后，再扩展到 4 和 8。
这样可将反复执行的 `M≈1024` GEMM 变为更少的 `M≈B*1024` GEMM，减少 CPU 启动开销，
同时保持优化器更新语义不变。

### 2. 按形状拆分 MiSS 路径

解码及很短的行数继续使用融合归约、投影和加法算子。
训练/预填充将 X 以 FP32 累加归约到连续 FP16/BF16 S，再用 cuBLASLt 计算
`S @ D.T` 和 `G.T @ S`。rank 16 是原生 Tensor Core 形状，当前自定义投影使大部分
Tensor 算力闲置。通过基准确定切换点，不要让所有行数都走同一路径。

对 dX，在有收益时将 `dS = G @ D` 与模 rank 散射融合，同时为大行数保留
cuBLASLt 加散射方案。每个微批次结束时将 dD 累加到 FP32 主梯度，
在文档规定的容差内保持确定性累积。

### 3. 减少重放与启动开销

通过 Nsight 区间判断，保存归约后的 S、部分层输入或 WKV 中间结果是否比重算更划算。
提供显式的内存/性能模式，不应默默增加计算记录。
张量地址和适配器目标稳定后，用 CUDA Graphs 捕获静态完整分块的前向/反向启动序列。
用多张量算子合并 FP32 主副本到 FP16 的刷新、Adam 更新和梯度清零。

### 4. 调优主要基模与 WKV 算子

仅在阶段 1–3 改变形状且新追踪明确剩余主要耗时算子后开展。
对实际 `(M,N,K,dtype)` 集合调优 cuBLASLt 算法并持久化缓存。
WKV 在 SM120 上测试块大小、寄存器压力、共享内存使用、状态布局和向量化加载。
严格保持现有状态传递边界；每次布局变更后比较完整序列与分块的状态和梯度张量。

### 5. HIP 对齐

将稳定的形状分派和批次语义移植到 HIP，独立选择 rocBLAS/hipBLASLt 算法，
不要直接照搬 CUDA 启动参数。在声称对齐之前，必须在真实 AMD 硬件上运行相同的
参考、有限差分、检查点、分块和状态传递测试。

## 验收条件

每个阶段必须保持现有正确性检查全部通过，且不增加基模 dW。
对上述 7.2B 命令，记录 tokens/s、步耗时中位数、峰值显存、功耗、SM 活跃度、占用率、
Tensor 活跃度、DRAM 活跃度和耗时前十的算子。
首个实际目标是在损失和检查点语义不变的前提下实现至少 1.5 倍 token/s，
随后达到至少 70% SM 活跃度和 35% Tensor 活跃度。
若首次干净的 Nsight Systems 追踪表明 WKV 或其他非 Tensor 工作导致更低上限，
应据此调整目标。
